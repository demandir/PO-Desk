# Architecture and security model

```text
Browser ── GitHub Pages (static site)
   │
   └── HTTPS ── Neon Function `api` ── Neon Postgres
```

- **Requesters** have no account. They submit a request and receive one private request code. Only its hash is stored, and a lookup returns status and dates only.
- **Admins** sign in with a username and password. Passwords are stored as scrypt hashes in `auth.users`. A successful sign-in returns a signed 8-hour token, held in the browser tab's session storage.
- **Authorization** is enforced by Postgres. For each request the function opens a transaction, switches to the `authenticated`, `anon`, or `service_role` database role, and sets the user id. Row-level security then limits department admins to their department, and global admins see every department.
- **Status changes** write append-only audit events. References, timestamps, and totals are generated by the database.
- **Abuse controls** are per-address and per-username rate limits, an origin allowlist, input validation in `functions/validation.ts`, and a Content Security Policy in `index.html`. GitHub Pages cannot set response headers, so the policy is a meta tag.

The site uses `#/` routes and relative asset paths, so it works at any Pages path. No email is collected or sent.
